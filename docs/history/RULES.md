# docs/history/ 폴더 규칙

이 디렉토리는 기술 변경 이력과 검증 리포트를 시간순으로 관리한다.

---

## 폴더 네이밍

```
{index}_{brief_title}_{YYYYMMDD}_{HHmm}/
```

| 요소 | 설명 | 예시 |
|------|------|------|
| `index` | 2자리 순번. 기존 최대값 +1 | `01`, `04`, `12` |
| `brief_title` | 작업 내용을 snake_case로 간략히 | `ffmpeg_h264_drive_upload` |
| `YYYYMMDD` | 작업 수행 날짜 | `20260225` |
| `HHmm` | 작업 시작 시각 (24h) | `1930` |

예시: `03_ffmpeg_h264_drive_upload_20260225_1930/`

## 리포트 파일 네이밍

```
{index}_{brief_title}_{YYYYMMDD}_{HHmm}.{lang}.md
```

| 요소 | 설명 | 예시 |
|------|------|------|
| `lang` | 주 서술 언어 (ISO 639-1) | `ko`, `en` |

- 리포트 파일명은 폴더명과 동일하되 `.{lang}.md` 확장자를 붙인다.
- 한/영 혼재 시 서술 비중이 높은 쪽을 선택한다.

예시: `03_ffmpeg_h264_drive_upload_20260225_1930.ko.md`

## 폴더 내부 구조

```
{index}_{brief_title}_{YYYYMMDD}_{HHmm}/
├── {index}_{brief_title}_{YYYYMMDD}_{HHmm}.{lang}.md   # 리포트 (필수)
└── {부속 자료}/                                          # 스크린샷, 로그 등 (선택)
```

- **리포트**: 폴더당 1개. 배경, 원인/결정, 구현, 검증 결과, 남은 작업을 포함.
- **부속 자료**: 스크린샷, 로그 파일, 설정 파일 등 리포트에서 참조하는 자료.

## 주의사항

- 폴더명이 과도하게 길어지지 않도록 title은 3~4 단어 이내로 유지한다.
- 같은 날짜에 여러 작업이 있으면 index와 HHmm으로 구분된다.
- 기존 폴더의 index나 이름은 변경하지 않는다. 새 작업은 항상 다음 번호로 추가한다.
